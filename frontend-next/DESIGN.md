\# Default



\## Overview



Default token theme for the UI Colors Design Token Builder.



This is a token-driven interface with coordinated light and dark color modes. The structured tokens above are the normative source of truth. The current token set does not define a product audience, brand personality, or emotional direction; add that context here when it becomes available.



\## Colors



The primitive palettes are Zinc, Bamboo, Orange, Green, Red, Blue. Semantic roles cover Surface, Text, Border, Primary, Secondary, Success, Warning, Danger, Info, Chart, Brand 1, Brand 2, Brand 3.



Use unsuffixed semantic color tokens for light mode and the matching `-dark` token for dark mode. Components should consume semantic colors instead of primitive palette values so that intent and theming remain intact.



\## Typography



Use Sora for default interface text and Sora for display styles. Available complete text styles are `display-large`, `display-medium`, `display-small`, `heading-large`, `heading-medium`, `heading-small`, `text-medium`, `text-small`, `label`. Apply each style as a unit so family, size, weight, line height, and letter spacing stay synchronized.



Preserve the authored casing of text; the current styles do not apply a text transform.



\## Layout



Use the `size-\*` spacing scale for dimensions and gaps. Current form layout uses these resolved values:



\- Field group gap: 1.25rem

\- Field control gap: 0.75rem

\- Field content gap: 0.25rem



No grid, breakpoint, container-width, or responsive-layout rules are encoded in the current tokens.



\## Elevation \& Depth



Elevation uses the following CSS-compatible shadow recipes. Shadows live in prose because the current DESIGN.md alpha schema has no structured top-level shadow group.



\- `shadow-1`: `0 1px 2px 0 color-mix(in srgb, oklch(0.141 0.005 285.823) 5%, transparent)`

\- `shadow-2`: `0 1px 3px 0 color-mix(in srgb, oklch(0.141 0.005 285.823) 10%, transparent), 0 1px 2px -1px color-mix(in srgb, oklch(0.141 0.005 285.823) 10%, transparent)`

\- `shadow-3`: `0 4px 6px -1px color-mix(in srgb, oklch(0.141 0.005 285.823) 10%, transparent), 0 2px 4px -2px color-mix(in srgb, oklch(0.141 0.005 285.823) 10%, transparent)`

\- `shadow-4`: `0 10px 15px -3px color-mix(in srgb, oklch(0.141 0.005 285.823) 10%, transparent), 0 4px 6px -4px color-mix(in srgb, oklch(0.141 0.005 285.823) 10%, transparent)`

\- `shadow-5`: `0 20px 25px -5px color-mix(in srgb, oklch(0.141 0.005 285.823) 10%, transparent), 0 8px 10px -6px color-mix(in srgb, oklch(0.141 0.005 285.823) 10%, transparent)`

\- `shadow-6`: `0 25px 50px -12px color-mix(in srgb, oklch(0.141 0.005 285.823) 25%, transparent)`



\## Shapes



Use the `radius-\*` tokens from the frontmatter. Component-specific radius choices are captured in the structured component tokens and should remain consistent within each component family.



\## Components



\- \*\*Buttons:\*\* Use the `label` text style, a 2.25rem height, 0.75rem radius, and 1rem horizontal padding. Primary and secondary interaction colors come from their matching semantic action tokens.

\- \*\*Inputs:\*\* Use the `text-medium` text style, a 2.25rem height, 0.75rem radius, 0.75rem horizontal padding, and the `outline` border treatment.

\- \*\*Cards:\*\* Use 1.5rem internal spacing, 1.5rem between child elements, a 1rem radius, and `shadow.2` for elevation.

\- \*\*Badges:\*\* Use a 0.375rem radius.



Border colors and shadow assignments remain documented here rather than in component frontmatter because those property names are not part of the current DESIGN.md alpha component schema.



\## Do's and Don'ts



\- Do use semantic color tokens for component styling.

\- Do switch all semantic color roles together when changing color mode.

\- Do apply typography tokens as complete styles.

\- Don't replace semantic colors with primitive palette values inside components.

\- Don't invent brand, layout, motion, or accessibility rules that are not yet documented.
